# Listing updates

Treat every "update listings" request as a review of **all sources used by this project so far**, not only the latest additions or the main Resolve subreddit. Follow [Every listings update](WEBSITE.md#every-listings-update) and [Contributing](CONTRIBUTING.md).

Build the source checklist from the maintained discovery/evidence ledgers, existing listings, credits and local research follow-up notes. Include every previously used source and retain newly discovered sources for future runs. Record inaccessible or incomplete checks explicitly; do not silently skip sources or claim exhaustive coverage.

Research reports, raw captures and private bookmark data stay local and must not be committed or uploaded. New listings require original-source verification and reviewed search tags. Maintenance-only changes do not warrant a catalogue release.

Every listings update must preserve the full public update trail: review prior catalogue releases, record verified provider or plugin changes with their original release or changelog links, keep individual resource release references visible, and regenerate the public Updates page. Never publish personal information, contact details, credentials, private files, local filesystem paths, bookmark-export details or other private identifiers in catalogue records, changelogs, releases, generated pages or issue forms.

## Readable release notes

For every future **update listings** run, write GitHub release notes, the changelog and website updates in plain language for Resolve users:

- Give each tool a clear, recognizable heading.
- List changes as short bullets, with one change per bullet. Explain what changed and any material requirement or limitation.
- Show readable version numbers. Label repository revisions **Source update**; keep full commit hashes in structured version/history data and source links.
- Describe each new resource briefly, including its purpose and access model.
- Link the original provider notes with descriptive link text. Keep raw upstream changelog dumps and unexplained jargon out of the visible prose.
- Preserve earlier releases and exact version history. Show a local preview before publishing GitHub or website changes.

Follow the release-note guidance in [WEBSITE.md](WEBSITE.md#every-listings-update).
